### 2.3 已核实的差异和问题

| 项目 | 原版实现 / 当前事实 | 本轮处理方向 |
| --- | --- | --- |
| PPO 生成与更新 | 原版每个外层 epoch 由 vLLM 集中生成 ATR、RA，随后切换到 Transformers/TRL 更新；当前改成按批实时生成后更新 | 还原原版流程 |
| checkpoint | 原版每个外层 epoch 保存一次；当前每个 update 保存一次 | 还原按 epoch 保存 |
| 最佳模型对应关系 | 原版用本轮训练前分数选择本轮训练后权重，分数与权重错位 | 保留并完善必要修复 |

| 奖励白化 | 原配置 `whiten_rewards=true`；当前实现强制 false | 恢复 true 并实测有限值 |
| 奖励实现 | 原版 SR 奖励使用 `## ...` 标题数量代理；当前正则及部分解析约束与原函数不完全一致 | 以原函数语义为准，不能把 token 统计混入奖励 |
| 输出位置 | PPO、传统/RL 权重、仿真记录、results、W&B 分散；部分文件以固定名称写入 | 统一派生到独立实验目录 |

## 3. 修改、还原、保留的明确边界

### 3.1 必须还原的 PPO 行为

| 内容 | 拟执行动作 | 还原后的规则 |
| --- | --- | --- |
| 生成后端与流程 | 移除当前默认 Transformers 按批生成/立即更新方式，恢复原版 vLLM 集中生成 | 每 epoch：加载当前策略→集中 ATR→集中 RA→释放推理模型→TRL 更新→保存 epoch |
| 训练轮数和批量数值 | 按用户最新要求保留小样本；原数值另存参考 | 当前2 epochs、batch4、mini2、累积1、ppo_epochs1、lr=1e-5；参考为100/32/2/16/2 |
| 量化 | 恢复原 PPO 的 4bit NF4、double quant、BF16 计算、gradient checkpointing | 不以不量化版本替代原基线 |
| LoRA | PPO 恢复 r=8、alpha=16、dropout=0；取消 all-linear 作为默认 | 保留原版 PEFT 默认选择方式，并记录实际层名；当前 PEFT 对相关架构通常命中 q_proj/v_proj，须检查确认 |
| 白化 | 取消强制关闭 | `whiten_rewards=true` |
| PPO 生成参数 | 保留采样协议；测试输出预算按资源约束 | temperature=0.1、top_k=50、top_p=0.95、当前max_tokens=1024，参考2048；上下文8192 |
| checkpoint 时机 | 取消默认 update_N 模型保存 | `epoch_1/`、`epoch_2/`……；每个 epoch 的所有 update 只写指标 |
| 验证协议 | 取消默认每个 update 的贪心验证 | 使用原版 vLLM 验证协议，按 epoch 评估，修复权重对应关系 |
| 奖励定义 | 对照原函数恢复奖励和有效输出解析语义 | RA 对错奖励、used_atr、SR 标题计数及系数保持原版；token 数只用于日志 |
| 数据来源 | PPO 不再强制绑定那 5 条教师入选记录及 SFT 的小样本 manifest | 恢复从显式配置的原 PPO 交通记录数据源划分，eval_ratio=0.1、seed=42 |

原 YAML 声明了 `lr_scheduler_type=cosine`，但原 PPO 训练器创建过程没有实际接入该字段。本轮不能为了“配置看起来完整”新增原来没有生效的 scheduler；记录配置声明与实际行为的区别。同理，新增日志频率不会改变优化步骤。

原版在各个外层 epoch 重建模型和训练器。不能顺便改成跨 epoch 连续保留优化器、调度器或 value head 状态的另一套训练规则。常规下一 epoch 的初始化语义按原版保留；修复的是前一 epoch 策略 Adapter 的正确加载。若需要严格断点恢复，必须另行区分“恢复同一个未完成 epoch”和“开始正常下一 epoch”，不能混淆。

### 3.2 必须保留的已补齐功能

- 现有目录位置：`.venv/`、`llm_models/`、`CityFlow/`、`my_tests/`；原智能体源码 `models/` 保留。
- `.env` / `.env.example` 管理教师、学生和凭证；`config/config.yaml` 管理训练与实验。真实密钥不复制进日志、快照和报告。
- 用户真实百炼教师的 OpenAI 兼容调用、超时、失败处理、实际用量记录及数据生成进度恢复。
- 教师数据转换、数据清单、TRL-SFT、assistant-only 监督、SFT Adapter 保存和合并。
- SFT 合并产物作为 PPO 基础模型，避免退回原始学生模型而丢失 SFT 效果。
- 最佳 checkpoint 的验证来源、完整权重合并导出、独立加载验证、CityFlow 从配置加载指定完整模型。
- 路径规范化、原子写入、参数校验和已有测试。根据新的路径与基线规则更新测试，不能沿用已失效的期望值。

SFT 原仓库没有给出可直接执行的完整训练实现，因此其参数不能称为“恢复原参数”。现有 SFT 实现保留，参数标明为新增实现的设置；SFT 与 PPO 的 LoRA 配置分开管理，不因为 PPO 恢复默认目标层，就擅自更改已补齐 SFT 的目标层。

### 3.3 仅保留必要修复，不扩大方法修改

1. **真实 query 批量修复**：batch_size=32 表示 32 个 ATR/RA query，即 16 条交通记录；断言 `len(queries)=len(responses)=len(rewards)=32`。尾部不足一个完整批次按原版丢弃整对记录，记录丢弃数；不拆散 ATR/RA，不静默复制数据填满批次。
2. **提示与 token 一致性修复**：消除 system 文本重复拼接；vLLM 生成与 PPO 使用同一个 chat template 和实际 prompt/response token IDs，防止解码再编码改变序列。保留原提示内容，不重写推理策略。超长样本显式报错或按配置排除并记录，不静默截掉关键内容。
3. **模型加载修复**：在正确的基础模型上只加载一份 PPO Adapter，保证可训练参数集合正确；vLLM 下一 epoch 真正加载前一 epoch 的 Adapter。不能只保存了 Adapter，却在下一轮忽略它。
4. **最佳模型修复**：验证分数必须指向实际被验证的 checkpoint，所有 epoch（含最后一轮）都有机会参与选模，详见第 6 节。
5. **跨模型必要适配**：读取所选模型 tokenizer 的 chat template、EOS、PAD 和上下文限制，移除推理客户端中只适用于 Llama 的固定结束 token。适配 Qwen 不等于改写 PPO 算法。
6. **运行兼容修复**：解决 vLLM/Transformers 依赖冲突、补齐 4bit 依赖，必要时修复 API 调用与显存释放。不能遇到 vLLM 问题就静默退回 Transformers 训练流程。
7. **数据有效性**：缺少运行必需字段的记录隔离并报告。当前额外的“教师 RA 必须等于模拟器 Best_Signal 才能进入 SFT”过滤属于数据策略变化，改为显式可选项，基线默认不加这一额外筛选；不重标教师答案。去重、随机打乱和抽样也必须报告对覆盖率的影响，不能无记录改变原数据分布。

### 3.4 明确不顺手更改的内容

- 不改奖励系数、不把 SR 奖励的标题数量代理换成 token 惩罚，不新增 DPO 等训练目标。
- 不修改传统/RL 智能体的网络、损失、经验回放、更新节奏或选模规则；只调整输出接口和记录。
- 不按论文截图直接改信号配时、ATT/AWT/AQL 计算公式或归一化方式；先保存原始值、公式版本和统计范围。
- 不把缺少的异步调度、故障注入等悄悄塞入基线。新增实验模式必须显式开启、单独命名并记录。
- 不删除或移动已有历史实验，不把旧的小样本模型重命名成新基线训练结果。

`run_sft.py`、`ppo_ft.py` 等保留阶段模块及独立阶段调试能力，正式使用优先通过总入口。根目录不永久保留八份同名包装脚本，避免整理后仍然拥挤；本轮同步更新旧调用方，旧命令迁移表写入 TRAINING.md。已有权重路径和历史报告不做机械字符串替换。

目录迁移放在业务功能修复之前：先在阶段 A 留存基线，阶段 B 完成包结构、路径与入口骨架，再在新位置完成 SFT/PPO 修复及测试，避免最后搬迁导致重复修改和测试失效。

### 4.0.1 总训练入口与两个模式

`train_collmlight.py` 负责读取配置、校验所选阶段、创建唯一 run_dir、组织阶段进程、收集日志/指标、选模及最终导出；不实现第二套 SFT/PPO 算法，也不自动调用 CityFlow 评测。

```text
共同前置：配置及资源检查 → 新建/显式恢复实验
          → 按需采样/教师生成或验证已有输入 → SFT 数据准备

training.enable_ppo = false
  → SFT 训练及验证 → sft_best → 合并导出 trained_best_model → 结束

training.enable_ppo = true（默认）
  → SFT 训练及验证 → sft_best → sft_merged
  → 原版流程 PPO 训练及验证 → ppo_best
  → 合并导出 trained_best_model → 结束

后续用户单独运行 run_CoLLMlight.py，加载所选实验的完整模型做评测。
```

数据准备采用明确配置：`training.data_preparation: reuse` 为默认，校验已有交通记录、教师数据及来源后转换；需要真实调用教师时显式设为 `generate_teacher`；需要从 CityFlow 采样再生成教师数据时设为 `sample_and_generate`。generate_teacher 可恢复同一任务进度，但不根据“文件缺失”自行开启付费请求；reuse 缺输入应报错并说明如何准备。各模式都归档输入摘要和筛选/划分，不因启用 PPO 重复生成同一批教师数据。

优先用同一 `.venv/bin/python` 分阶段子进程执行模块，显式传入冻结配置与同一 run_dir，日志进入各阶段 attempt 目录；进程结束释放 GPU 后再启动下一阶段，避免 SFT、vLLM、PPO 同时驻留。入口捕获返回码和异常，某阶段失败则停止下游，状态标记为 failed，不把旧目录或仅存在文件当成成功。实现不得调用 shell 拼接未经转义的路径。

仅 SFT 模式的 PPO 阶段状态记为 `skipped_by_config`，不创建虚假的 PPO 指标/checkpoint，不要求 PPO 数据或初始化 vLLM；仍检查 SFT 本身所需依赖。如果选 SFT＋PPO，启动前检查 PPO 的必要环境和数据容量，避免做完长 SFT 才发现明显阻碍；结束时用实际 sft_best 身份重新确认 PPO 输入。

`enable_ppo` 和有效模式固定在初始快照及 manifest：`sft_only` / `sft_ppo`。`--resume-run` 不允许改变模式或关键数据/模型配置；从已完成的 SFT-only 实验继续比较 PPO 时新建实验，通过显式 SFT 来源复用，不原地改开关覆盖旧的 SFT-only 导出。

### 4.0.2 公平比较：复用同一份 SFT 最佳产物

拟提供可选 `training.sft_source_run: null`：为空时本次正常训练 SFT；显式指定已完成实验时，校验其 sft_best、基础模型摘要、数据与划分清单、SFT 配置和阶段验证记录，再复用它，不再次训练 SFT。仅接受具有可追溯训练记录和 best 清单的来源；其他模型路径另按导入协议校验，不能从任意 Adapter 猜测。

推荐对比方式：先以 false 训练一次 SFT 并保留其完整模型；再以 true 新建实验且指定上述 SFT 来源，仅接续该 SFT 的 PPO。子实验记录 parent_run、source_sft_checkpoint/hash、源配置和本次 PPO 配置，SFT 状态写为 `reused`。两份完整模型分别评测，保持路网、流量、推理参数和对应 seed 一致。true 从头训练时也保留明确的 sft_best，便于以后单独导出它进行对比。

源实验只读，不删除、不改写；复用清单归入子实验，导出模型仍是完整独立权重。若为节省空间引用源 Adapter/基础模型，须记录该依赖，源缺失就明确报错，不能误称子实验训练 checkpoint 已自包含。源来源变化或配置不匹配不静默兼容。

拟采用以下结构。所有路径均位于 `CoLLMLight-master/` 内，基础模型和数据集可作为只读输入共享，不要求每次复制一份。


仅 SFT 分支不生成 sft_merged/PPO 产物，直接把基础模型与 sft_best 合并为 trained_best_model，避免同一权重多存一份。新 SFT 的规范名称统一为 sft_best，迁移当前依赖 sft_adapter 的调用方；历史 sft_adapter 目录原样保留并通过显式旧格式读取兼容。传统固定策略不产生训练权重时不制造空模型文件；用 manifest 记录“不适用”。它们和 RL 算法沿用自己的训练/测试过程，统一的是产物归档方式。

已有的 `outputs/qwen15b_smoke/`、`qwen15b_round2/` 等保持原位置及可加载性；新流程不强制迁移旧实验。新旧模型路径均允许通过配置指定。

### 4.1 实验名称与防覆盖

- 运行名严格采用 `<实验名称>_<YYYYMMDD>_<HHMMSS>_<ffffff>`，最后六位为微秒，不增加 UUID 或随机编号。
- 使用带时区时间，manifest 记录时区和 UTC 时间；延迟测量使用单调时钟，不使用文件名时间相减。
- 微秒时间戳通常足以区分单机运行，但操作系统时钟精度、回拨等仍可能导致重名。因此用原子创建目录并要求目录不存在；撞名就明确报错，不复用旧目录、不覆盖文件，也不自动添加另一套编号。
- 同名实验再次启动生成新时间戳，得到新目录。算法名和实验名校验为合法目录名。
- 一个总入口创建一次实验上下文，然后向教师、SFT、合并、PPO、导出传递同一 `run_dir`。不能每个阶段各生成一个时间戳，把同一次训练拆成多个实验。
- 每次 CityFlow 评测在训练实验的 `evaluations/` 下创建独立评测目录。不同数据集、seed、消融条件和重复测试均不覆盖之前记录。
- 对外部已有完整模型，可创建新的“仅评测实验”，manifest 指明训练来源，避免向来源不明的目录写入。

### 4.2 新训练、阶段续接和断点恢复分别处理

| 操作 | 行为 |
| --- | --- |
| 新实验 | 创建新 run_dir，拒绝复用已有目录 |
| 同一实验下一阶段 | 显式传入 run_dir，检查上游产物与阶段状态，完成阶段不默认重做 |
| 教师任务恢复 | 显式恢复原 run_dir 的进度，校验数据/模型/请求参数签名，追加调用与用量记录 |
| 新基线 PPO 恢复 | 先支持已完成 epoch 边界恢复；校验基础权重、LoRA 结构、数据划分、基线配置与下一 epoch 编号 |
| 未完成 epoch 重跑 | 标记失败尝试，另建该 epoch 的 attempt 日志，重新生成/训练该 epoch；不宣称从中间 update 精确续跑 |
| 从旧模型启动新实验 | 新建 run_dir，记录 parent_run 和来源；不能覆盖父实验 |
| 再次 CityFlow 评测 | 新建 evaluation 目录，固定所加载的模型清单及权重摘要 |

原版没有完整的优化器断点保存。本轮默认不再为每个 update 保存优化器；epoch 边界恢复应遵循原版下一 epoch 重建训练器的语义。保存恢复所需的进度、随机状态及来源信息，不以“完善恢复”为由改变常规训练规则。中途 update 的严格恢复不是本轮默认承诺。

旧 `update_N` checkpoint 的 all-linear、无量化及训练协议不同，不能静默接入新的原版基线。旧权重的推理和完整模型导出保留；若尝试训练恢复，先进行兼容性校验，不兼容则拒绝并说明，不伪装成同一基线连续训练。

### 4.3 统一所有写入位置

拟新增轻量的实验路径对象，例如 `utils/experiment.py`，由各入口共享，派生 models/logs/metrics/records 等路径。实现清单包括：

- 教师任务：原共享 `syn_rt_data.json` 改为本实验 `data/teacher/` 内的产物；原始公共数据仅作输入。
- SFT、PPO、合并、完整导出：全部使用实验 models 子目录。
- `run_CoLLMlight.py`、`framework/CoLLMlight.py`、`framework/FTSample.py`：results、性能 JSON、LLM 原始响应、图片和状态日志从上下文派生。
- 传统/RL 的各 `run_*.py`、`utils/pipeline.py`、`utils/oneline.py`、生成器、测试器与总结模块：通过既有 `dic_path` 等接口传递模型和仿真目录，补充指标导出。
- 扫描所有固定 `results/`、`records/`、`model/`、`ppo_checkpoints/`、`llm_weights/`、`data/FinetuneData/` 写入点及按天命名的文件，逐项登记并迁入实验路径。
- `utils/utils.py` 的清理逻辑不再删除归档所需的模型、日志和车辆记录；可清理内容限于明确的临时产物。
- W&B 可保留，但不是唯一日志来源。缓存目录放在本实验下，恢复与新实验的身份分开管理，离线也能保留完整本地指标。
- `my_tests/` 仍保存测试代码和每次测试的独立报告/索引，测试产生的训练、仿真业务数据进入对应 outputs 实验，避免复制大权重。

## 5. 配置和依赖处理

### 5.1 单一配置来源

保留上一轮拆分：教师/学生和凭证仍在 `.env`，训练、归档、导出和 CityFlow 评测放在 YAML。拟增加如下概念，最终字段在实施时统一校验：

| 配置组 | 主要内容 |
| --- | --- |
| experiment | algorithm、name、output_root、时区；run_dir 为实际运行时生成/显式续接 |
| training | enable_ppo（唯一阶段开关）、data_preparation、sft_source_run；见4.0.1—4.0.2 |
| teacher_data | source_path、max_samples、进度恢复；输出默认由实验目录派生 |
| data | SFT/PPO 各自数据来源和划分；过滤策略、划分单位和固定 seed |
| sft | 已补齐 SFT 的训练参数、日志频率、checkpoint/验证与阶段选模设置 |
| ppo | 原版训练参数、vLLM 生成参数、4bit、LoRA、白化、按 epoch 保存 |
| logging | 本地 JSONL/CSV、原始响应、flush、W&B 和记录粒度 |
| export | source=auto，依据唯一开关解析为 sft_best 或 ppo_best；完整导出、完整性与加载验证 |
| cityflow_test | model_path、后端/服务端连接、数据集、流量文件、时长、seed |
| experiments | 延迟基准、消融、故障注入；新增模式默认关闭 |

配置示例（拟新增字段，不表示当前配置已修改）：

```yaml
training:
  enable_ppo: true              # true：SFT＋PPO；false：仅 SFT
  data_preparation: reuse       # reuse / generate_teacher / sample_and_generate
  sft_source_run: null          # 复用同一 SFT 时填写来源实验目录
sft:
  save_strategy: epoch
  eval_strategy: epoch
  best_metric: eval_loss
  greater_is_better: false
export:
  source: auto                  # 总入口根据 enable_ppo 唯一解析
  auto_export: true
cityflow_test:
  model_path: null              # 配合显式 --run-dir 选择实验；也可填完整模型路径
```

以上是有关字段片段，实施时并入完整 YAML，保留现有 SFT/PPO 其他设置。`enable_ppo` 只接受 YAML 布尔值，拒绝字符串 false 等歧义输入，不再新增第二个独立 mode 开关。总训练入口必须导出最终完整模型：若 auto_export=false，启动前拒绝这一冲突并说明；独立调试阶段可不导出，但不能报告完整训练交付成功。显式 export.source 与所选模式冲突时报错，不关闭 PPO 却读取旧 ppo_best。

`cityflow_test.model_path` 为空时，评测入口必须通过 `--run-dir` 明确选择实验，再定位其 `models/trained_best_model/`；填写路径则使用该完整模型，并单独明确评测归档上下文。两种方式同时给出且来源冲突时拒绝。不会因为加载 `training.enable_ppo=true` 而在评测入口发起训练，也不按“最新目录”猜测模型，不能加载失败后退回基础模型。

原始训练配置与调通配置分开：原版参数单独保存为参考，当前活动配置明确采用小样本值；`my_tests/configs/` 内显式设置少轮数、少记录、短仿真。所有覆盖值保存到本次 effective config，不把测试的 batch=2、max_updates=1 留作正式默认值。

完整训练的 SFT 不保留当前 `max_steps=2` 的截断；设置为按指定 epoch 完成，准确记录新增 SFT 的参数来源。教师原版最多抽取 1000 条，保留可配置的原版抽样模式；另提供显式“全部有效记录”模式。二者不能混称，也不把“全量”悄悄解释成 5 条调通样本。

按交通记录划分后再展开 ATR/RA，防止同一记录进入两边。PPO 恢复原版数据源和 0.1 验证比例，SFT 使用明确记录的独立划分；同时报告两阶段的 ID 重叠。不能将被 SFT 学习过的样本上的 PPO 分数称为独立测试成绩。四个真实路网作为最终零样本评测，不用于调参或挑选 PPO best。

### 5.2 依赖最小修复顺序

1. 用 `.venv/bin/python` 记录 Python、包版本、包元数据要求、CUDA/GPU、CityFlow 路径和可用磁盘，备份环境清单。
2. 先检查已经安装的包，满足要求的不重复安装。不新建另一套环境替代用户的 uv 环境。
3. 保留 TRL 0.9.2 既有 PPO API 为优先目标；评估满足 vLLM 0.9.1 下限的 Transformers 版本，与现有 PEFT、tokenizers、SFT 同时做兼容测试，然后锁定实际通过的版本。若需改 vLLM 版本，比较依赖影响后选择改动较小且真实通过的组合，不盲目整体升级。
4. 检查后补齐缺失的 bitsandbytes，并验证真实 Qwen 模型 NF4 4bit 加载、LoRA 反传和保存重载。仅 import 成功不算通过。
5. 完成真实 vLLM 生成、LoRA 加载、TRL PPO step，以及原 SFT/CityFlow 回归。依赖一致并不自动代表运行兼容。
6. 新安装或调整的包追加到工作区根目录 `/root/autodl-tmp/new_requirements.txt`，记录原版本→新版本、原因和阶段，不覆盖旧记录。

兼容组合未实测前，不写“已解决”。上述 PPO 兼容检查针对两阶段模式及其专项验收；用户仅运行 SFT 时不应因未安装 vLLM 或未提供 PPO 数据而失败，但 SFT 若启用4bit，仍必须满足其量化依赖。如出现阻碍，保留错误日志和最小复现，不通过关闭白化、取消量化或更换 PPO 生成范式掩盖问题。

## 6. checkpoint、选模、完整模型与空间

### 6.1 保存规则

- PPO 默认 `save_strategy=epoch`，保留所有已完成 epoch。100 轮通常为 100 份 LoRA checkpoint，加一份当前最佳 Adapter；不是数千份 update checkpoint。
- checkpoint 保存原训练器 `save_pretrained` 所需的 Adapter、value head 等实际内容，附必要进度和来源。它不是完整 1.5B/8B 模型，也不等于原版有完整优化器恢复状态。
- 取消将完整优化器状态逐 update 写入的默认行为。可选的额外恢复策略必须明确开启、单独估算空间，不改变原版默认保存方式。
- 每个 update 的 loss、KL、reward 等仍全部写日志。因此取消 update 模型文件不会丢失训练曲线。
- `ppo_best/` 保留最佳 checkpoint 的推理所需增量权重与来源清单；训练结束只合并导出选定的 best，不为每个 epoch 导出完整模型。
- SFT 属于补齐模块，必须增加按 epoch 验证与 Adapter checkpoint，依据验证 loss 选择 sft_best；其 best 与 PPO best 分开标记，PPO best 仍按原版 RA 奖励选择。

### 6.1.1 仅 SFT 与两阶段共用的 SFT 最佳模型选择

1. 固定训练/验证记录划分，先划分再展开 ATR/RA，训练 loss 不参与选 best，CityFlow 测试数据不参与选 best。
2. 默认每个完成 epoch 保存 Adapter 并验证，绑定相同 global_step、checkpoint 权重摘要、验证数据摘要及有限的 eval_loss。选 loss 最低者，严格改善才替换，平分选较早 checkpoint。
3. 训练达到 max_steps 而停在 epoch 中途时，对最终实际更新后的状态执行保存和验证；同一步已有完整记录则不重复计数，避免短程测试或提前结束漏掉候选。正常短测试至少产生两个可比较的真实候选。
4. 保存 `models/sft_best/` 与选模清单，记录 best_step/epoch、eval_loss、样本/token 计数及原 checkpoint。不能把最后一轮自动当 best；零次更新、空验证集、非有限 loss 或没有有效候选时停止导出，不回退旧模型。
5. 仅 SFT 分支：用原始未量化学生权重＋sft_best 合并为完整 trained_best_model，执行独立加载及真实 ATR/RA 验证。无需创建 PPOTrainer、value head 或调用 PPO 验证。
6. 两阶段分支：同一个 sft_best 合并为 sft_merged，作为 PPO 的固定基础模型；不是使用 SFT 最后一轮，也不直接退回原始学生。

SFT 的“最佳”是固定验证集上最低监督 loss，PPO 的“最佳”是其固定验证集上最高平均 RA reward；二者均不代表已经证明具有最小 CityFlow ATT。交通效果比较应在模型选定后通过独立测试完成。

“最佳模型＋最近少量 checkpoint”确实也能支持已记录实验的图表，但本轮按用户要求默认恢复保留全部 epoch，不擅自启用滚动删除。保留全部 checkpoint 方便重测历史策略；仅保留日志不能事后为已删除模型补做新仿真实验。

### 6.2 修复原版 best 的最小执行安排

原版第 e 轮开始时，vLLM 载入的是 e−1 轮权重，不能把此时的分数关联到第 e 轮训练后的文件。

优先采用复用原版加载节奏的修复：

1. 首轮加载 SFT 基础模型，其验证分数仅记为初始参考。
2. 后续轮开始时，评估当前实际加载的 `epoch_(e-1)`，将分数和权重摘要绑定到该 checkpoint，再比较 best。
3. 本轮完成 PPO 更新后保存 `epoch_e`，等待下一轮开始时验证。
4. 最后一轮结束后追加一次 vLLM 验证，确保 `epoch_N` 也参与选择；单轮训练同样必须执行这次验证。

这样不需要每个 update 验证，也避免为了修复 best 每轮额外重复加载推理模型。选择指标维持原版验证集平均 RA reward，严格大于才替换，平分保留较早的最佳项。初始 SFT 分数不冒充完成 PPO 的候选。

每条验证记录包含 checkpoint 路径/摘要、epoch、累计 update、数据划分摘要、生成参数、RA/ATR reward。`ppo_best` 的选择清单指向真正被验证过的权重。目录采用临时写入、完整性检查、完成标记和安全切换，失败时保留上一份完整 best，防止删掉旧 best 后新 best 复制失败。

### 6.3 `trained_best_model/` 保留并加强来源校验

导出器显式支持两种来源，不再强制要求每次都有 PPO 文件：

```text
仅 SFT：原始学生 + 已验证 sft_best → trained_best_model
两阶段：原始学生 + 已验证 sft_best → sft_merged
           sft_merged + 已验证 ppo_best → trained_best_model
之后均由用户独立运行 run_CoLLMlight.py 评测
```

最终目录包含完整 config、tokenizer、generation_config、模型权重/分片索引，以及导出来源和验证报告；不能只有 `adapter_model.safetensors`。

导出时校验所选分支的基础权重、Adapter 和对应阶段 best 验证记录；manifest 写明 training_mode、selected_stage、选模指标和值、源 checkpoint/hash、基础模型及可选父实验。仅 SFT 不要求 progress 中存在 PPO update 或 RA 最优奖励；两阶段必须有 PPO 来源，不允许 PPO 失败后自动导出 SFT 并声称两阶段完成。用未量化基础权重正确合并增量；分别记录 NF4 训练/验证与完整 BF16 推理的精度差异。比较合并前后输出和允许误差，不要求量化与未量化 logits 完全相同；若验证结论变化，报告差异，不能悄悄重新挑一个测试集 best。

训练中的 best 可能被更好 checkpoint 替换，属于同一次实验的正常选模。已经完成并对外用于评测的完整导出不静默改写；后续恢复训练产生新导出时保存独立版本和来源，评测目录固定其模型身份。

### 6.4 空间检查而不是固定承诺

两阶段新增空间按以下项目估算：SFT Adapter/阶段 checkpoint＋一份完整 sft_merged＋N 份实际 PPO epoch checkpoint＋一份 ppo_best＋一份完整 trained_best_model＋教师/生成文本/仿真日志＋临时合并及依赖下载缓存。仅 SFT 模式不预算 PPO checkpoint 或额外 sft_merged，但仍预留 SFT checkpoint、完整最终模型及临时合并空间；预检按实际模式和是否复用 SFT 分别计算。

Qwen2.5-1.5B 的单份 BF16 完整权重约 3 GB 量级，但不能据此保证当前剩余空间一定足够。当前 all-linear checkpoint 还带优化器状态，其大小不能直接用于估算恢复原版后的 checkpoint；先测量真实 r=8 默认目标层保存结果，再外推 100 轮，并预留临时导出空间。

不自动删除旧实验释放空间。报告可用空间、各阶段预估与不足项，空间不足在启动大任务前明确提示，避免训练到最后无法保存 best。

## 7. 日志、JSON 和指标记录

### 7.1 文件职责

当前截图中的 `sft_report.json`、`merge_report.json`、`export_report.json` 等属于不同阶段摘要，并非同一模型被重复保存。Adapter 的 `adapter_config.json`、完整模型 `config.json` 则是模型加载文件，必须随模型保存。

拟整理为：模型配置留在 models 内；报告进入 reports；配置/版本进入 config；样本进入 data；逐次训练与评测数据进入 metrics；原始响应按 JSONL 流式保存并引用。取消每个 update 新建顶层报告、同时在 summary 中重复嵌入全历史的组织方式。

同一实验内的当前状态摘要可以原子更新，但历史事件和指标追加保留。阶段重试使用单独 attempt 日志，不把旧 `real_sft.log` 以 `w` 模式覆盖。初始配置快照固定保存，每次阶段的有效配置和覆盖参数另存，不反复覆盖同一 `resolved_config.json`。

### 7.2 最低记录字段

| 记录 | 必需内容 |
| --- | --- |
| 实验身份 | schema_version、algorithm、run_id、stage、attempt、时间、seed、代码/配置/数据摘要 |
| SFT train/eval | epoch、global_step、loss、eval_loss、lr、可用时的 grad_norm、样本/token 数、耗时、阶段 checkpoint |
| PPO train | epoch、global_update、批次交通记录数/query 数、RA/ATR reward、TRL 返回的 policy/value/total loss、KL、entropy、clip 统计、lr、长度和耗时 |
| PPO eval | 被评估 checkpoint 身份、RA/ATR reward、合法动作率、样本数、生成参数与 best 选择事件 |
| 教师 | 请求次数、重试、耗时、API usage、成功/失败数、sample_id、模型名；不保存 Authorization |
| CityFlow | dataset/traffic/roadnet 摘要、seed、仿真秒数、动作步、intersection、phase、逐步 queue/waiting/reward、车辆进出记录与最终 ATT/AWT/AQL/throughput |
| LLM 调用 | SR/RD 模块、batch_id、实际 batch_size、请求/完成时间、batch_wall_time、prompt/completion token、finish_reason、模型/后端/生成参数 |
| SR 观测关联 | SR 使用的观测时刻、结果生成时刻、RD 消费时刻、own/neighbor 观测车辆数、去重集合数量、SR 输出 token 数 |
| 扰动 | 实际模式、独立 seed、随机抽样结果、受影响邻居、缓存年龄、故障发生与恢复事件 |

TRL 各版本返回键不同：保存其实际可用的数值统计，并建立稳定字段映射；缺失字段记为 null 并写原因，不填假零。原生 token 和奖励标题计数分别命名。JSONL 保存细节，CSV 导出平坦字段，摘要只保存聚合值、样本数和原始记录位置。

### 7.3 指标口径和低干扰采集

- 现有 `avg_atr_time` / `avg_ra_time` 以调用总耗时除以交叉口数，属于摊销值，不能直接当成 batch=1/5/10 的整批延迟。新增完整批次 wall time，保留旧值但明确名称和单位。
- SR token 数用实际生成 token IDs 统计；需要同时记录用于 RD 的可见文本 token 数、被移除的 thinking 内容、EOS/特殊 token 口径。不能用单词数、字符数或奖励函数中的标题数替代。
- SR 车辆数绑定该次 SR 真正看到的本路口及已通信邻居观测；优先使用车辆 ID 并集去重，同时保存分项。若原数据只含计数，必须注明口径和局限，不伪造可去重的 ID 或用全网车辆数替代。
- ATT/AWT/AQL 保留原代码统计方式，输出单位、网络求和/路口平均、时间平均方式、未完成车辆处理等定义及原始数据。需要不同口径时另列 derived 字段，不能覆盖原指标。
- 基准计时执行 warm-up、重复与批次完整性检查；GPU 计时在独立 benchmark 中正确同步。常规异步实验不能为了计时加入全局同步而改变调度。
- 事件缓冲和适当 flush，记录异常及中断状态；日志失败不能让实验被标成成功。比较开启日志前后的动作序列与调用次序，验证采集没有改变默认算法。

### 8.1 新增实验功能与基线的边界

为了覆盖表2和表4，确实需要新增实验模块，不能只改日志字段。这些模块属于“补缺失的实验能力”，默认关闭，原仓库执行路径作为 `original` 明确保留。

- `sync_sr`：显式等待本步 SR 完成，再供本步 RD 使用；绑定观测时间。
- `async_sr`：独立调度 SR，RD 使用已完成的历史 SR 与最新观测；需要缓存、任务生命周期和关闭策略，以及启动时无 SR 结果的明确处理。用提交/完成/消费时间证明是否真的非阻塞，不能仅改函数名。
- `without_sr`：使用现有禁用 SR 的能力，并验证不调用 SR、不把未清理缓存送入 RD；保留 RD 的其他基线行为。
- `stale_sr`：按截图以 0.5 概率额外延迟一个决策时间步；记录原本应使用与实际使用的 SR 版本，不能将“总是使用上一步 SR”当成扰动。
- `communication_failure`：以 0.5 概率使一个随机选中的邻居通信失败；记录邻居、抽样时刻与不可用标记。不能改成每个邻居独立丢弃 50% 或把车辆数直接写成零。

截图未明确的首步、故障抽样粒度等实现细节将在实验协议中明示，不声称是作者未公开的实现。新增异步/故障实验作为独立模式验收；如用户仅批准基线修复与采集，这些表格对应条件标记为待实现，不能声称全部论文实验已具备。

### 8.2 AR/PR 消融的实际权重

| 变体 | 真实过程 |
| --- | --- |
| Ours | 原版自适应推理数据→SFT（AR）→PPO（PR）→完整导出 |
| w/o PR | enable_ppo=false：相同 AR/SFT 的 sft_best 合并完整模型后评测，不加载 PPO Adapter |
| w/o AR | 不执行 AR 的自适应数据训练，明确选择原基础模型或协议规定的非自适应 SFT 起点，再执行相同 PR；将起点写入协议 |
| w/o Both | 不执行 AR 和 PR，使用指定的未微调基础模型 |

原仓库未完整提供论文全部消融训练入口，尤其 w/o AR 的确切非自适应训练细节不能由截图唯一推出。默认采用明确标注的“去掉 AR 阶段、基础模型直接 PR”实验，并注明这一选择；不宣称已还原作者私有设置。四个变体各自 manifest 固定来源、阶段开关和数据，之后分别运行 CityFlow。

总训练入口的默认两模式只覆盖 Ours 与 w/o PR 的阶段组合，不把 enable_ppo=false 解释成 w/o AR。w/o AR 的 PPO-only、w/o Both 的基础模型评测仍由独立消融入口组织，复用相应模块，不能扩大 enable_ppo 的含义或把 SFT 默认关掉。

本轮提供单次实验的 JSONL/CSV 和字段说明，以及能从原始记录核算汇总值的检查程序。不会把不同算法结果自动合成比较图表，也不会填入尚未运行模型的数据。

## 10. 分阶段修改与测试方案

以下测试文件名是拟新增内容，命令也属于实施后的目标接口，本文不声称它们当前已存在或已通过。

测试解释器统一为 `/root/autodl-tmp/CoLLMLight-master/.venv/bin/python`，实际检查 `sys.prefix`。学生为本地 `llm_models/Qwen2.5-1.5B-Instruct`；教师使用现有 `.env` 的真实 `qwen3.7-plus` 和业务地址，不替换为 mock 来宣称集成通过。

### 阶段 A：基线留存与环境检查

工作：留存原版/当前版/配置与差异，建立方法边界清单；只读记录数据量、磁盘、包依赖和旧产物身份，再解决第5.2节依赖阻碍。

拟测试：`my_tests/test_stage3_preflight.py` 与真实依赖探针。验证同一 uv 解释器、CityFlow 实际导入路径、vLLM/TRL/SFT 导入、真实模型 4bit 加载及最小生成。必要新增包逐项登记，保存调整前后清单。

验收：vLLM 与 Transformers 的要求一致，真实模型可加载；没有未解释的训练栈冲突。传统 TensorFlow 算法若有历史依赖问题单独报告，不能通过训练工具的全局环境开关误伤它们。

### 阶段 B：源码结构、训练入口骨架、配置与统一归档

工作：先建立 training/collmlight 包并迁移脚本、更新所有调用引用，新增总入口和唯一阶段开关；实现不执行模型任务的预检/计划输出，新增实验上下文，打通训练/仿真各路径，禁用归档清理。先验证路径与编排接口，再在阶段 C/D 接入修复后的真实阶段，不能等业务修复结束才迁移。

拟测试：`my_tests/test_stage3_experiment_paths.py`、`test_stage3_training_entry.py`、`test_stage3_module_layout.py`。

- 连续启动同名实验获得两个不同目录；注入相同时间戳必须拒绝覆盖，不增加 UUID。
- 同一 run_dir 的阶段续接复用上下文，重复已完成阶段会报出明确状态。
- 模拟错误退出/重试后旧日志、配置与指标仍在，JSONL 无无声截断。
- 同一模型同一数据集评测两次分别归档；旧实验文件校验不变。
- 在项目外工作目录运行，所有相对配置路径仍正确解析。
- 扫描并实测输出边界，除用户指定的登记文件与测试报告外，新业务产物均在对应 run_dir。
- 包导入和总入口 --help/--dry-run 不读数据、不调教师、不初始化 GPU；历史 refinement 导入也无任务副作用。dry-run 不创建正式实验，明确显示即将执行的阶段、数据准备方式及所需资源。
- 模块方式与直接脚本方式的配置/根路径解析一致；从项目外执行绝对脚本路径也正确。测试导入、内部调用和文档引用不再指向已搬走的根脚本。
- enable_ppo 默认 true，false 正确只规划 SFT；字符串 false、冲突 export.source、缺来源模型或同一 run_dir 切换模式均被拒绝。
- 编排测试用阶段桩检查顺序、同一 run_dir、子进程解释器、失败停止和 skipped/reused 状态；此阶段桩只验证编排，不能代替 C/D/E 的真实集成。
- 仅 SFT 的计划和阶段调用不会导入或启动 vLLM/PPO，也不会检查 PPO 专属样本容量；reuse 缺教师数据不会自动付费调用。

本阶段还用短程真实 CityFlow 运行验证路径，不单靠创建假文件证明可用。

### 阶段 C：教师、SFT 和合并保留性验证

工作：在迁移后路径实现教师私有输出和恢复；SFT 增加逐步日志、按 epoch 的 checkpoint/验证及 sft_best 选择，接入总入口 false 分支和 SFT 完整导出。该分支先独立跑通，再接入阶段 D 的 PPO，不等待全部 PPO 修复结束才验证新开关。

拟测试：`my_tests/test_stage3_teacher_sft.py` 及真实阶段脚本。

- 至少1条真实交通记录调用真实教师 ATR/RA 两次，核对模型名、usage 和输出；随后恢复验证不重复请求已完成项。
- 复用已记录来源的真实教师样本，以本地学生执行实际 SFT 优化，验证 LoRA 权重变化、train/eval 日志、记录划分互斥及 assistant-only labels。
- 真实合并并重新加载，生成真实 ATR/RA；teacher/SFT/merge 全部归在同一实验中。
- 通过 train_collmlight.py 且 enable_ppo=false 启动真实短训练，至少保存并验证两个更新后候选，核对 sft_best 确实对应最低 loss、训练/验证日志完整，trained_best_model 可独立生成真实响应。
- 使用选模逻辑测试覆盖“最优不是最后一份”、平分、NaN、空验证集和 max_steps 中途结束；真实候选不要求恰好出现 loss 先降后升。
- 检查 false 分支没有 PPO 调用、checkpoint、指标或奖励依赖，完成清单含 sft_only 与选模来源；数据生成模式用真实教师测试，reuse 模式确认新增教师请求为零。

验收：不是只验证 HTTP 200、import 或文件存在；必须有实际响应、训练更新和重新加载证据。不会为验收默认生成全部付费数据。

### 阶段 D：原版 PPO 路径恢复及硬性修复验证

工作：恢复 vLLM 集中生成、4bit TRL 更新、原版目标层/白化、epoch 保存；修复批量、模板、Adapter 与 best 对应关系。

拟测试：`my_tests/test_stage3_original_ppo.py` 和真实 PPO 集成脚本。

- 使用真实本地学生/SFT 产物、真实有效交通记录，完整通过 vLLM ATR→RA→释放→4bit TRL step→epoch 保存→下一轮 vLLM 加载该 Adapter。
- 至少做两轮外层小规模真实实验，检验 epoch_1、epoch_2、训练后最后一轮验证及 best 选择。
- 按最新资源要求，本轮实际验收batch=4、mini=2、grad_acc=1、ppo_epochs=1、whiten=true、4bit；原版batch32/grad_acc16/ppo_epochs2留待扩容后专项验收，不声称已经通过。保持独立有效记录和非空验证集，不复制样本伪造数量。
- 检查当前真实4个 query、有限 loss/KL、LoRA 参数更新、冻结基础权重、实际目标层，及训练/推理 Adapter 身份。
- 检查两轮只产生两份 epoch checkpoint，不产生默认 update_N 模型目录；每个 update 的统计仍完整。
- 纯逻辑测试构造验证先高后低与平分情况，证明导出选的是实际 best 而非最后一轮；这类选择测试可用小型桩数据，但不能替代上面的真实训练。
- 从已完成 epoch 边界恢复，验证下一 epoch 编号、数据/模型签名、旧指标和历史 best 保留；不承诺未实现的 update 中途精确恢复。
- 使用 train_collmlight.py 的 true 分支真实接入以上 PPO 流程；它必须使用已选 sft_best 的合并权重。复用阶段 C 的 SFT 来源时不重做 SFT、不修改父实验，检查 parent_run、reused 状态及权重摘要一致。
- 模拟 PPO 失败检查总入口退出失败、保留 SFT 和错误日志，不把 SFT 完整模型冒充 sft_ppo 最终结果；失败后按原配置恢复，旧 best 和日志不覆盖。

短程测试只限制外层轮数和真实数据范围。任何缩短输出长度等额外覆盖明确列入测试有效配置；当前8192上下文/1024生成预算已实测，2048输出及更大batch在扩容后另测。100轮全量长训练不作为代码修改后的默认测试自动启动。

### 阶段 E：最佳完整模型与 CityFlow 衔接

工作：完善 sft_best/ppo_best 两种完整导出与选模来源校验；恢复原服务端推理入口并保留显式本地后端。run_CoLLMlight.py 始终只评测，不因读取训练开关而启动训练。

拟测试：`my_tests/test_stage3_best_export_cityflow.py`。

- 校验 best 对应 checkpoint 和验证记录，真实合并并独立加载完整模型，检查分片和 tokenizer 完整性。
- 在隔离加载环境中不依赖 Adapter 加载路径完成推理，确认不是伪完整模型。
- 用真实导出模型进行短程 CityFlow；至少验证本地路径及原协议兼容服务端路径。服务端启动参数、服务模型名和实际权重路径写入报告，不能以接口成功代替权重来源核对。
- YAML 改为另一份有效完整模型时必须实际加载该模型；无效路径/Adapter 路径要明确报错，不自动回退。
- 同一评测重复两次，检查两份日志与指标独立存在。记录合法决策、兜底次数和样本数，不因短训模型效果差而伪造零兜底。
- 分别用阶段 C 的 SFT-only 完整模型和阶段 D 的 SFT＋PPO 完整模型做真实 CityFlow 短测，配置指向哪份就加载哪份，保存对应 mode/source/hash；SFT-only 的评测不能要求 ppo_best 文件存在。
- 检查评测进程不调用 train_collmlight、SFT 或 PPO，不改变训练完成状态。缺 --run-dir 且缺 model_path 时不能自动猜选“最新实验”。

### 阶段 F：日志覆盖和论文实验入口

工作：完成第7—8节采集与默认关闭的新增实验模式。

拟测试：`my_tests/test_stage3_metrics.py`、`test_stage3_experiment_modes.py` 及真实推理 benchmark。

- 用真实学生执行 SR/RD 的 b=1/5/10 基准，每种条件 warm-up 后多次重复，检查整批时间、实际批量、token 和环境元数据。
- 短程 CityFlow 验证原始 queue/waiting/车辆记录能核算原代码汇总值；SR token/车辆观测逐条关联。
- 在固定 seed 和确定性可控条件下对比新增记录前后动作与调用顺序，确认采集不改基线路径。
- 调度模式用受控慢 SR 探针检验 RD 是否等待，再做真实模型短程验证；Normal、额外 stale、单邻居通信失败分别产生可检查事件。随机行为测试检查规则和可重复性，不要求小样本恰好50%命中。
- 检查 AR/PR 四种组合的真实来源及阶段开关；集成验收可用小样本短训产物，不伪称完整消融训练已完成。
- 四个真实路网分别进行短程加载/指标采集验证；其他算法至少验证传统策略与一种已有 RL 训练入口的归档，再逐一验证本次涉及的其余入口。原有依赖缺失导致无法运行的算法列为未完成项，不能以静态检查冒充实测。

这些测试证明记录和入口可用，不代表已经完成论文全部模型、数据集、长时长和重复 seed 的正式实验。

### 阶段 G：总测试、产物核对与交付

- 用新实验名通过总入口完整串联 false 分支：显式真实教师生成→转换→真实 SFT→验证选 sft_best→完整导出；再单独用 run_CoLLMlight.py 做 CityFlow 测试并核算原始日志。
- 新建 true 分支，显式复用上述相同 SFT 最佳产物→原版路径 PPO→验证选 ppo_best→完整导出，再单独评测；另外以短程真实配置从总入口执行默认 true 的从头 SFT→PPO 完整流程；可复用已生成的真实教师数据，不能跳过实际 SFT 训练或用阶段桩代替。false、true 从头及 true 复用 SFT 三种运行方式分别报告通过状态。
- 执行新增 `my_tests/`、原有 `tests/` 回归。需真实模型的集成测试通过专用入口运行，记录 skip 和失败原因，不用大量 skip 后的“全绿”代替完成。
- 重复启动新实验并重复评测，验证旧模型、日志、指标校验值保持不变。
- 汇总实际测试参数、模型身份、依赖变更、资源占用与各阶段输出路径，并列出相对原版的全部方法差异。
- 给出正式全量运行命令、恢复命令、测试模型路径配置示例和数据字典；测试文件及报告位于 `my_tests/`，对应业务产物位于独立 outputs 实验内。

## 11. 用户确认后的执行顺序与最终验收

实施顺序调整为：A 留存基线及必要环境检查 → B 源码迁移、统一入口/开关和实验上下文 → C 先跑通 SFT-only 选模导出 → D 接入原版 PPO 并验证 true 分支/共享 SFT 来源 → E 两种模型独立 CityFlow 评测 → F 论文实验采集与扩展 → G 两分支总验收。目录、配置、日志接口在前期统一，不能先完成旧路径业务后才补搬迁和开关。

每阶段修改后完成本阶段测试并记录结果，再进入下一阶段；C/D 尚未接入的入口阶段要明确报未实现，不允许假成功。A 中发现仅影响 PPO 的阻碍不应使用户的 SFT-only 入口依赖 PPO；两阶段完整交付前仍必须修复并实测。

最终验收条件：

1. 运行名符合用户指定格式，无 UUID；新实验和重复评测均不覆盖旧结果。
2. 一次算法实验的模型、日志、指标、原始记录和配置归入同一目录，历史实验保持可用。
3. PPO 恢复原版 vLLM/4bit/LoRA/白化/批量/epoch checkpoint 基线；必要修复有证据和测试，不残留未说明的方法替换。
4. 最佳验证分数与保存的权重一致，最后一轮参与选模；完整 trained_best_model 可独立加载并由 CityFlow 实际使用。
5. 训练过程有本地逐步记录，表1—4、图3—4所需字段及新增实验条件分别有明确来源；缺少的模型/长训练/正式评测如实列出，不声称已跑出未执行的实验。
6. 所有环境/真实教师/真实学生/CityFlow 测试有可检查报告；新依赖先检查后安装且完成登记。
7. 八份脚本完成约定迁移且引用一致，新增 training/collmlight/train_collmlight.py；对比算法原入口、framework 两份实现和 models 智能体目录职责保持不变。
8. enable_ppo 默认 true；false 真实完成 SFT 验证选 best、完整导出且没有 PPO 执行。true 真实完成 SFT＋原版 PPO，两个分支的最终权重均可被同一 CityFlow 评测入口加载；可追溯地复用同一个 sft_best 进行效果比较。

确认范围包括：源码结构前置调整、统一训练入口和默认开启 PPO 的唯一开关、两分支验证选模与完整导出、同源 SFT 复用、原 PPO 方法恢复、必要修复、统一归档与采集、独立 CityFlow 衔接，以及第8节默认关闭的缺失实验模块。本文保留整合方案与本轮实施边界；实际结果以第三轮测试报告为准，不是全量训练或论文性能复现成功的声明。

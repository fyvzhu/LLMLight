## 三、目录迁移方式

### 3.1 迁移前检查

只读检查以下事项并保存迁移清单：

- 目标目录是否已经存在，是否有重名或用户新增文件；不覆盖、不混合不明来源目录。
- 是否仍有训练、推理服务或仿真进程使用旧目录。
- 基础模型文件清单、大小及校验值；现有训练报告、Adapter、checkpoint 的位置与引用。
- CityFlow 在当前解释器中的实际 `__file__`，是否以 editable / `.pth` / `.egg-link` 方式引用旧源码目录。
- 工作区与目标目录可用磁盘空间。基础模型和 CityFlow 目录同文件系统时优先使用移动，避免重复复制大权重。

### 3.2 执行迁移

```text
/root/autodl-tmp/models
    → /root/autodl-tmp/CoLLMLight-master/llm_models

/root/autodl-tmp/CityFlow
    → /root/autodl-tmp/CoLLMLight-master/CityFlow

/root/autodl-tmp/test
    → /root/autodl-tmp/CoLLMLight-master/my_tests
```

同步更新：

- `STUDENT_MODEL_PATH`、基础模型默认路径、测试模型路径。
- 新增测试中的 `ROOT` / `PROJECT` 定位逻辑、解释器定位及日志输出目录。
- 测试入口、采样复测输出位置、汇总报告脚本。
- `README.md`、`TRAINING.md`、测试报告生成模板中的命令和相对路径。
- 项目扫描/测试发现范围：避免将嵌套 CityFlow 的测试、构建产物或大模型文件误作本项目测试输入。

所有运行路径以 `CoLLMLight-master/` 为基准解析。测试既从项目根目录运行，也从另一个工作目录使用绝对脚本路径运行，验证不依赖偶然的当前目录。

### 3.3 保留已有 Adapter 和 checkpoint 的可用性

不能只修改新的 `.env`：已有 SFT Adapter 的 `adapter_config.json` 可能仍指向旧基础模型目录。

- 逐个检查本项目已生成 Adapter 的 `base_model_name_or_path`。
- 仅将确认属于本次移动的基础模型旧路径映射到新路径，修改前保存可回溯记录。
- 检查 PPO Adapter 引用的 `sft_merged` 是否仍有效。
- 验证第一轮已有 SFT、PPO 最佳 Adapter 的加载，以及已有 PPO checkpoint 的恢复。
- 不对模型二进制做字符串替换，不改写旧训练指标、样本内容或历史评估结果。
- 历史报告中的旧路径可作为历史事实保留，用迁移映射和新报告说明当前位置；当前入口必须解析到新位置。

### 3.4 CityFlow 安装与构建路径

- 移动源码不等于一定需要重新安装；先测试现有环境中的扩展能否导入并推进仿真。
- 如果 editable 引用仍指向旧源码、扩展无法加载或重新构建需要旧绝对路径，再使用现有 `.venv/bin/python` 对迁移后的源码进行安装/构建。
- CityFlow 的 CMake 缓存可能含旧绝对路径。必要时使用新的构建目录，不复用失效缓存；不无差别删除源码或已有用户文件。
- 不修改 C++ 仿真算法，不升级系统驱动，不重建整个 uv 环境。
- 依赖先检查再处理；必要的新增依赖/版本变化追加到现有 `new_requirements.txt`，不覆盖第一轮记录。

## 四、配置拆分与唯一来源

### 4.1 `.env` / `.env.example` 保留什么

保留“选择和连接教师/学生”的配置：

```dotenv
# 教师模型与接口；真实值仅放在 .env
TEACHER_MODEL=qwen3.7-plus
TEACHER_BASE_URL=https://你的业务空间地址/compatible-mode/v1
TEACHER_API_KEY_ENV=DASHSCOPE_API_KEY
DASHSCOPE_API_KEY=
TEACHER_TEMPERATURE=0.1
TEACHER_ENABLE_THINKING=false
TEACHER_MAX_TOKENS=2048
TEACHER_TIMEOUT_SECONDS=120
TEACHER_MAX_ATTEMPTS=2
TEACHER_USE_ENV_PROXY=false

# 学生基础模型与通用加载设置
STUDENT_MODEL_PATH=./llm_models/Qwen2.5-1.5B-Instruct
STUDENT_DTYPE=auto
STUDENT_MAX_LENGTH=8192
STUDENT_MAX_NEW_TOKENS=1024
```

实际 `.env` 沿用用户已有教师地址、模型和密钥，不把密钥复制到本文或 YAML。`.env.example` 的地址使用占位符，密钥为空，并按教师、学生分组增加注释和空行。

教师采样数量、任务随机种子和是否恢复属于“本次数据生成任务”的设置，迁入 YAML 的 `teacher_data`；教师连接/生成参数留在 `.env`。学生基础模型路径留在 `.env`；最终 CityFlow 测试模型路径位于 YAML，二者不是同一个角色。

### 4.2 `config/config.yaml` 管理什么

包括实验名称、输出路径、数据设置、LoRA、SFT、PPO、最终模型导出与 CityFlow 测试。拟定结构如下，具体字段在实现中保持单一语义：

```yaml
experiment:
  run_name: qwen15b_smoke
  random_seed: 42
  output_root: ./outputs

teacher_data:
  source_path: ./data/FinetuneData/SynTrain_sample_all.json
  output_path: ./data/FinetuneData/syn_rt_data.json
  max_samples: 5
  random_seed: 42
  resume: true

data:
  eval_ratio: 0.2
  sft_require_ra_match: true

sft:
  lora:
    rank: 8
    alpha: 16
    dropout: 0.0
    target_modules: all-linear
  learning_rate: 0.0001
  num_epochs: 1
  per_device_batch_size: 1
  gradient_accumulation_steps: 1
  gradient_checkpointing: true
  quantization_bits: 0
  max_steps: 2
  logging_steps: 1

ppo:
  lora:
    rank: 8
    alpha: 16
    dropout: 0.0
    target_modules: all-linear
  learning_rate: 0.00001
  num_epochs: 1
  batch_size: 2                 # 实际 query 数：一条交通记录产生 ATR、RA 两项
  mini_batch_size: 1
  gradient_accumulation_steps: 1
  optimization_epochs: 1
  max_updates: 1
  max_new_tokens: 1024
  temperature: 0.1
  gradient_checkpointing: true
  quantization_bits: 0

export:
  source: ppo_best
  output_dir: null             # null → 当前实验的 outputs/<run_name>/trained_best_model
  device: cpu
  dtype: auto
  validate: true

cityflow_test:
  model_path: null             # null → 当前实验导出的 trained_best_model；也可填其他完整模型路径
  backend: transformers       # 小模型本地集成验证，复用现有 Transformers
  dataset: synthetic_4x4
  traffic_file: anon_4_4_synthetic_8000.json
  run_counts: 60               # 首次两次控制周期的短程集成测试，不代表正式基准
  max_new_tokens: 1024
  seed: 42
```

这里 `null` 表示按当前实验计算默认路径，不采用未经实现的 `${...}` 字符串插值。用户填入显式 `cityflow_test.model_path` 时必须使用该路径；不存在或不是完整模型时明确报错，不能偷偷回退到基础学生模型。

### 4.3 消除重复与优先级

- `config/config.yaml` 是唯一有效的训练 YAML。
- 旧 `config/ppo_config.yaml` 在确认已无有效引用后移除；必要的历史内容记录在说明中，不继续保留两份看似都生效的配置。
- 将训练参数从实际 `.env` 和 `.env.example` 移出，避免它们继续覆盖 YAML。
- 模型相关参数：显式命令行覆盖 > 进程环境变量 > `.env` > 默认值。
- YAML 管理参数：显式命令行覆盖 > 指定 YAML > 默认值；旧的同名环境变量不隐式覆盖训练 YAML。
- 提供 `--config` 和 `--env-file`，默认分别定位项目 `config/config.yaml` 和 `.env`。
- 配置加载可在内部映射到现有 `TrainingConfig` 键，减少训练代码改动，但所有阶段使用同一个解析结果。
- 未知 YAML 字段、重复键、非法数值、拼错的布尔值和无效路径应有明确校验；密钥不得进入日志或脱敏配置快照。
- 各阶段只校验自身所需配置：导出/本地测试不要求提供教师密钥。

## 五、导出完整的 `trained_best_model/`

### 5.1 明确导出的对象

本轮导出的是：

```text
本次实验的 sft_merged/（完整 SFT 模型）
    + ppo_best/（由验证集选出的最佳 PPO Adapter）
    ↓ 安全合并与独立加载校验
outputs/<run_name>/trained_best_model/
```

这份模型已经包含 SFT 和 PPO 的参数效果，并且对应 `ppo_best` 的验证结果。它不是最后一次 PPO 更新的同义词。

第一轮实例中 `update_2` 的验证奖励低于 `update_1`，因此应导出 `ppo_best` 对应的 `update_1`，而不是更新序号最大的 `update_2`。该实例将作为选模正确性的回归用例。

当前 SFT 仍保存训练结束权重。本轮不把它误称为“全程全局最优 SFT 模型”；`trained_best_model` 的“best”指以该 SFT 起点进行 PPO 后的最佳验证 checkpoint。若以后补充 SFT 多 checkpoint 选模，再沿同一导出接口衔接。

### 5.2 新增导出入口

计划新增 `export_best_model.py`，负责：

1. 从 `ppo_best` 读取对应的 Adapter、验证结果和 checkpoint 来源，确认基础模型是正确的 `sft_merged`。
2. 校验权重、模型架构、tokenizer、相位输出协议和来源文件是否匹配；来源不明或缺少验证结果时拒绝标记为已验证最佳模型。
3. 使用非量化基础权重加载最佳 PPO Adapter，执行 `merge_and_unload(safe_merge=True)`；不将 value head 当作推理语言模型权重合并。
4. 合并前后在相同输入、相同 dtype 下比较 logits；容差根据 dtype 明确设置并记录。
5. 保存完整基础配置、合并权重、tokenizer、聊天模板和 generation config。
6. 以导出后的实际保存精度重新加载，并与“相同精度的基础模型 + 最佳 Adapter”作数值/输出检查。
7. 将完整模型重新用于相同验证记录，保存导出后的评估结果；如果序列化精度导致决策变化，明确报出，不能仍宣称与最佳 checkpoint 完全一致。
8. 完整导出和验证成功后才发布到最终目录；先写独立临时目录，避免中途失败留下看似完整的最终模型。

`dtype: auto` 根据已验证加载精度、设备和内存选择，并记录实际值；不无条件转为 BF16。8B 导出前检查主存与磁盘，提供设备/精度配置，不将“必须重写导出脚本”留给后续换模型。

### 5.3 最终目录内容

```text
trained_best_model/
├── config.json
├── generation_config.json
├── model.safetensors                 # 或标准分片权重及 index
├── tokenizer.json
├── tokenizer_config.json
├── tokenizer 所需其他文件
├── model_manifest.json
└── export_validation_report.json
```

`model_manifest.json` 记录原始学生、SFT 基础模型、最佳 PPO checkpoint、验证分数、导出精度和来源校验信息，不保存密钥。

推理只依赖该目录。清单中可以记录来源路径，但推理不应再要求原始基础模型或 Adapter 路径仍然存在。

### 5.4 与 PPO 保存流程衔接

- 每次最佳 checkpoint 更新时记录明确的 `best checkpoint` 元数据，且验证分数对应同一份权重。
- 默认训练正常结束后调用统一导出函数；也支持独立执行 `export_best_model.py`，使第一轮已有 `ppo_best` 不必重新训练就能导出。
- 从 checkpoint 恢复后，如果新权重没有超过历史 best，不覆盖已有最佳权重；导出仍来自历史 best。
- 导出目录已存在时比较来源；匹配则可验证后复用，来源不匹配则明确提示，不静默覆盖另一实验模型。
- 不在本轮无提示删除旧 checkpoint。训练保留策略可后续单独配置，避免目录迁移时混入清理行为。

## 六、CityFlow 测试模型路径的实际接入

仅在 YAML 写一个路径而不使用它，不能算完成衔接。本轮将配置读取连接到实际加载入口。

### 6.1 路径语义

- `.env` 的 `STUDENT_MODEL_PATH`：SFT 的原始基础模型。
- YAML 的 `cityflow_test.model_path`：CityFlow 控制器本次实际使用的完整推理模型，可以是导出的最佳模型，也可以是用户指定的其他完整模型。
- 默认解析到当前实验 `trained_best_model/`；启动日志和测试报告记录最终使用路径及模型来源。

### 6.2 接入与短程验证

- 为训练产物测试提供明确入口，复用原有路网配置与 CoLLMLight 控制逻辑，并接入统一配置。
- 原 `run_CoLLMlight.py` 若接入 YAML，则显式 `--model_path` 优先；其旧默认占位符不得反过来遮蔽 YAML 中的真实路径。
- 短程集成测试采用现有 Transformers 本地加载后端，支持已有 `batch_ask` 等调用约定；避免为验证路径额外引入或升级 vLLM/lmdeploy 依赖。
- 远程推理服务仍需显式指定服务地址和 served model name；写了本地模型路径不等于服务已经部署。不得连接到一个仍加载旧模型的服务却报告测试了新模型。
- 检查首时刻历史不足、空路口默认动作、相位编码、模型 EOS token 等衔接问题；仅修复阻塞本轮集成验证的内容。
- 如果原推理入口因可选绘图、W&B 或传统 RL 依赖提前失败，采用延迟导入或本地日志方式，使本地推理验证不依赖无关服务。
- 首次用实际 Synthetic 路网跑至少两个控制周期，并确认至少发生一次真实 LLM 决策。若尚无车辆/未发生 LLM 调用，不能仅凭仿真推进就判定集成通过，应延长至有调用或明确失败。
- 检查动作属于四个合法相位，保存模型路径、LLM 调用次数、解析结果及交通指标，证明不是全程兜底动作。

该测试证明导出模型可以进入仿真控制链路。济南、杭州、纽约完整时长的效果比较另行运行，不将短程仿真当成正式 benchmark。

### 7.3 真实教师与训练流程

调整 `run_real_stages.py` 及相关测试：

## 十、与后续 Llama-3.1-8B 的关系

本轮配置、导出与加载接口以模型 tokenizer/config 为依据，不硬编码 Qwen 路径、token ID 或模型尺寸。后续使用 Llama-3.1-8B 时通过 `.env` 更换基础模型路径，并根据实际 GPU 调整 YAML 中的批大小、长度、精度与量化设置。

8B 的训练资源和数值行为仍需届时实际验证，不能凭 1.5B 通过就保证任意 8B 配置通过。本轮确保工程入口、最佳模型导出和 CityFlow 测试加载不必再重写。

独立测试集划分、SFT 多 checkpoint 最优选模、全量路网 benchmark 与 checkpoint 自动清理不在用户此次四项修改的默认实现范围内；保留接口和结果语义，不声称这些功能已经完成。尤其 `trained_best_model` 对应验证集选出的 PPO best，最终 CityFlow 测试不反过来参与挑选该 checkpoint。
